4. Step-by-Step Detail

Step 0 Validate & Initialize CLI
What it does
  • Checks User Story file exists: specs/<feature>/
  • Validates git branches in BOTH repos (backend + frontend)
  • Creates feature/<feature> branches if missing
  • Displays progress tracker
Skip condition
If --from=<phase-id> is passed, skips validation and jumps to that phase directly.
Step 1a Plan Skill: vnr-plan
Invocation
Skill tool: vnr-plan
Internally reads: agents/vnr-planner.md
Outputs
  • specs/<feature>/plan.md
  • specs/<feature>/data-model.md
  • specs/<feature>/contracts/
  • specs/<feature>/research.md
Auto — Plan Review (Step 1b) runs immediately after.
Step 1b ✦ NEW Plan Review Agent: vnr-plan-reviewer
What it checks (18 checks)
  • P-01..P-05: Spec Coverage (AC, BR, VM, Data Dict, NEEDS CLARIFICATION)
  • P-06..P-09: API & Contracts (endpoints, permission keys, wrappers)
  • P-10..P-14: Architecture Alignment (Clean Arch, CQRS, layers)
  • P-15..P-18: Feasibility & Completeness (phase order, FK consistency)
Verdict logic
  • 🔴 Critical ≥ 1 → FAIL ⛔
  • 🟡 Warning ≥ 1, Critical = 0 → WARN ⚠️
  • Both = 0 → PASS ✅
HITL Checkpoint: Human reviews findings + decides: [approve] / [modify] / [reject → --from=plan]
Step 1c Tasks Skill: vnr-tasks
Invocation
Skill tool: vnr-tasks
Internally reads: agents/vnr-task-breaker.md
Outputs
  • specs/<feature>/tasks.md
Contains N tasks organized in parallel groups.
Auto — Tasks complete → Testcase Writer (Step 2) starts immediately. No user confirmation required.
Step 2 Testcase Writer Agent: vnr-testcase-writer
What it does
  • Reads wiki, spec, plan, tasks, contracts, UI detail
  • Output: testcases.md
  • Categories: API, UI, Authorization, Integration
  • Priority: P0 (Critical) / P1 (High) / P2 (Medium) / P3 (Low)
Output
  • specs/<feature>/testcases.md
Auto — Testcases complete → Implement (Step 3) starts immediately. No user confirmation required.
Step 3 Implement Skill: vnr-implement
Invocation
Skill tool: vnr-implement
Auto-detects scope from tasks.md path prefixes — dispatches sequentially:
src/backend/ → vnr-backend-developer
src/frontend/ → vnr-frontend-developer
src/app-mobile/ → vnr-mobile-developer
What it does
  • Loads tasks.md + plan.md + contracts + data-model
  • Executes tasks per phase, marks [x] when done
  • Stops if non-parallel task fails
  • Build must pass (0 errors)
Auto — Build success → Step 4 starts immediately. Auto-stop if build fails — user must fix then --from=implement.
Step 4 ✦ NEW Code Review Agent: vnr-code-reviewer
What it checks
  • AC/BR Completeness — every AC in spec.md has code
  • Task Completeness — every task in tasks.md implemented
  • Code Quality — naming, DRY, dead code, error handling, null safety
  • Logic Correctness — branches, off-by-one, async/await
  • Hardcode / Magic Numbers — no literals that should be config
Verdict logic
  • 🔴 Critical ≥ 1 or missing AC → FAIL ⛔
  • 🟡 Warning ≥ 1, Critical = 0 → WARN ⚠️
  • Both = 0 → PASS ✅
Reads: spec.md, tasks.md, wiki conventions, constitution
Auto-stop if FAIL — fix logic/AC violations then --from=code-review. PASS/WARN → Step 5+6 starts immediately.
Step 5 + 6 Architecture Review + Security Review (PARALLEL) Agent Parallel
4: Architecture Review
  • Agent: vnr-arch-reviewer
  • Reads: architecture standards, contracts, constitution
  • Runs: 14 checks BE + 10 checks FE
  • Verdict: PASS / WARN / FAIL
5: Security Review
  • Agent: vnr-sec-reviewer
  • Reads: permission standards, security-hooks, constitution
  • Runs: OWASP checklist (14 BE + 7 FE)
  • Verdict: PASS / WARN / FAIL
Auto — PASS/WARN → Step 7 starts immediately. Auto-stop if FAIL — user must fix then --from=arch-sec-review.
Step 7 E2E Stubs (Placeholder) Stub
What it does
  • Checks if src/frontend/e2e/<feature>.e2e.spec.ts exists
  • If not: creates minimal stub with test.todo() for P0+P1 testcases
  • Does NOT run any tests
  • Always passes — status: ⏭ STUB
Intent
Placeholder for automation team. Stub file references testcases.md (P0+P1). Automation team implements body separately.
No checkpoint — automatically proceeds to Step 8. Always ⏭ STUB.
Step 8 Report Agent: vnr-tech-writer
Invocation
Agent tool (general-purpose)
Reads: agents/vnr-tech-writer.md
Outputs
  • specs/<feature>/result/final-report.md
  • specs/<feature>/result/user-guide.md
Includes: summary table (Arch, Security, E2E Stubs), findings, files changed, sign-off checklist, user guide in Vietnamese.

6. Gate Conditions (from Constitution)

Transition Gate Condition On Failure
Step 1a → 1b Automatic — Plan Review runs immediately —
Step 1b → 1c plan.md approved by user (after reviewing plan-reviewer findings) Reject → fix plan → --from=plan
Step 1c → 2 Automatic — Tasks complete → Testcase Writer starts immediately —
Step 2 → 3 Automatic — Testcases complete → Implement starts immediately —
Step 3 → 4 Automatic if build success (0 errors) — both BE and FE Auto-stop, fix then --from=implement
Step 4 → 5+6 Automatic if Code Review PASS/WARN Auto-stop if FAIL, fix then --from=code-review
Step 5+6 → 7 Automatic if Arch PASS/WARN + Security PASS/WARN Auto-stop if FAIL, fix then --from=arch-sec-review
Step 7 → 8 Automatic — stub always passes —
Step 8 → Done Automatic — pipeline complete, artifacts ready for PR —

7. Recovery & Resume

# Resume from specific phase (reuses existing artifacts)
/vnr-auto-pipeline <feature> --from=plan ← re-run Plan (planner)
/vnr-auto-pipeline <feature> --from=plan-review ← re-run Plan Review only
/vnr-auto-pipeline <feature> --from=tasks ← from Tasks (plan approved)
/vnr-auto-pipeline <feature> --from=testcases ← from Testcase Writer
/vnr-auto-pipeline <feature> --from=implement ← from Implement (build fixed)
/vnr-auto-pipeline <feature> --from=code-review ← from Code Review (logic/AC fixed) ✦ NEW
/vnr-auto-pipeline <feature> --from=arch-sec-review ← from Arch+Sec Review (arch/sec fixed)
/vnr-auto-pipeline <feature> --from=e2e-stubs ← from E2E Stubs check
/vnr-auto-pipeline <feature> --from=report ← Report only

# When --from=<phase-id>: skips validation of prior steps,
# reuses existing artifacts (plan.md, tasks.md, etc.)
